View Transitions

Each link below navigates with the turbo router and uses the browser's native View Transitions API to animate the page change. Try clicking around and using the browser's back button.

How to test: the view-transitions layout opts in to both the turbo router (turbo-visit-control: enable) and view transitions (turbo-view-transition: same-origin). Both checks read from the page you are leaving, so navigating from the site home into here is a regular full page load; every link between the demo pages below will use turbo plus a view transition.

1. Shared element morph

A gallery of cards. Clicking a card morphs the card's hero panel into the detail page hero using a shared view-transition-name. Other content cross-fades.

2. Directional slide

A 3-step flow that slides forward on Next and slides back on Previous (or the browser back button), driven by the data-turbo-visit-direction attribute the turbo router sets on <html>.

3. Scale + fade variant

Replaces the default cross-fade with a subtle zoom animation. Useful for content-heavy pages where a horizontal slide would feel jarring.

How this demo is wired up

  • The view-transitions layout adds <meta name="turbo-view-transition" content="same-origin"> alongside the existing turbo meta.
  • The shared transition CSS lives in assets/less/pages/view-transitions.less.
  • Variant-specific keyframes are inline on each page so they only fire during that page's navigations.
  • The site header gets view-transition-name: vt-main-header with no animation, so it stays put while the content underneath morphs.
  • A prefers-reduced-motion: reduce rule zeros out the duration for users who opt out.
